# 초록불 내비

횡단보도 보행 신호의 잔여시간을 보고 걷는 길찾기 프로토타입입니다.
차량 내비가 "몇 초 뒤 초록불"을 보여주듯, 걷는 사람에게 횡단보도의 다음 초록불까지 남은 시간을 보여주고,
**거리만 본 경로**와 **신호를 본 경로**를 비교해 어디서 언제 건너는 게 빠른지 알려줍니다.

- `index.html` 하나로 동작합니다. 그대로 열거나 정적 호스팅(GitHub Pages, Netlify)에 올리면 됩니다.
- 신호는 기본적으로 **시뮬레이션**입니다. 서울 T-Data 인증키가 있으면 `server/`의 프록시로 실제 교차로 신호를 받아옵니다.
- 지도는 두 가지입니다. 처음엔 강남 테헤란로 일대를 실제 거리로 그린 **개략도**가 뜨고, 지도 버튼에서 **실제 지도**(OpenStreetMap)를 원하는 곳 주변으로 불러올 수 있습니다.

## 무엇을 보여주나

| 화면 | 내용 |
|---|---|
| 지도 | 횡단보도마다 지금 신호(초록/빨강)와 남은 초 수. 누르면 잔여시간 표시기(LED) 카드가 열립니다. |
| 횡단보도 카드 | 다음 초록불까지 남은 시간, 지금 건너면 몇 초 남기고 도착하는지, 다음 초록불이 켜지는 시각 |
| 경로 비교 | 거리만 본 경로와 신호를 본 경로의 소요 시간·대기 시간·도착 시각, 횡단 순서 안내, 출발을 늦춰도 되는 여유 |

경로는 **시간 의존 최단경로**로 계산합니다. 보도는 거리 ÷ 보행 속도, 횡단보도는 도착 시각의 신호 상태에 따라 대기 시간이 붙습니다.
남은 초록불이 "횡단 시간 + 여유"보다 짧으면 다음 신호를 기다리는 것으로 계산하므로 뛰어서 건너는 경로는 만들지 않습니다.

## 실제 지도 불러오기

지도 버튼(지도 모양 아이콘)을 누르고 중심(대전 시청역·정부청사역·대전역·유성온천역, 서울 강남역·역삼역, 내 위치, 지금 보는 곳)과 반경(500 m~1 km)을 골라 **불러오기**를 누르면
OpenStreetMap에서 그 영역의 길·횡단보도·신호등·지하철 출입구·건물을 받아와 같은 그래프 구조로 바꿉니다.

| 데이터 | 처리 |
|---|---|
| 보도(`footway=sidewalk`), 골목(`residential` 등), 공원길, 계단, 지하보도 | 걷는 길. 계단은 1.6배 느리게 |
| 큰길(`primary`·`secondary`) | 차도라서 걷지 않음. 횡단보도로만 건넘 |
| 횡단보도 way(`footway=crossing`) | 횡단 간선. way나 노드에 `crossing=traffic_signals`가 있으면 신호 횡단보도 |
| 노드로만 표시된 큰길 횡단보도(`highway=crossing`) | 양쪽 보도를 찾아 횡단 간선을 만들어 붙임 |
| 신호 횡단보도 60 m 묶음 | 한 교차로. 방위로 북·동·남·서 횡단보도를 정하고 4현시 계획을 만듦(이름은 `junction` 노드에서) |
| 신호 없는 횡단보도 | 마킹 있으면 4초, 없으면 2초 지연 |
| 끊긴 보도 끝 | 12 m 안의 길에 붙여 연결. 가장 큰 연결 덩어리만 남김 |
| `railway=subway_entrance`, 역 | 출발·도착 후보("강남역 10번 출구") |
| `traffic_signals:countdown`·`:sound`·`:vibration`, `button_operated`, `crossing:island`, `tactile_paving` | 횡단보도 카드에 잔여시간 표시기·음향신호기·보행자 버튼 등으로 표시 |

횡단보도 하나는 보통 연석-차선-연석처럼 여러 구간으로 그려져 있습니다. 경로 계산은 연석에서 건너기 시작할 때만 신호를 보고,
그때 횡단보도 **전체 길이**를 남은 초록불 안에 건널 수 있는지 판단합니다. 차도 한가운데서 기다리는 경로는 만들지 않습니다.

한 번 불러온 지도는 이 기기에 기억해 두었다가 다음에 열 때 다시 불러옵니다. 개략도로 돌아가면 기억을 지웁니다.

주소 끝에 장소 이름을 붙이면 그 곳의 실제 지도로 바로 열립니다. `#dunsan`(시청역·둔산), `#complex`(정부청사역), `#daejeon`(대전역), `#yuseong`(유성온천역), `#gangnam`, `#yeoksam`.

배포: https://chorokbul-navi.netlify.app (대전 둔산: https://chorokbul-navi.netlify.app/#dunsan)

## 대전

| 항목 | 상황 |
|---|---|
| OpenStreetMap 보행 데이터 | 둔산동(시청역 주변 약 1 km²)에 보도 way 363개, 횡단보도 way 209개, 횡단보도 노드 228개. 강남역 주변보다 훨씬 촘촘합니다. |
| 시청역 횡단보도 태그 | 신호 횡단보도마다 잔여시간 표시기, 음향신호기, 보행자 버튼이 표시돼 있고 출입구 1~8번이 모두 있습니다. |
| 실제 데이터 검증 | 시청역 주변 길 33개·노드 131개를 받아 테스트로 고정했습니다. 둔산로·둔산중로 사거리의 신호 횡단보도 4개가 한 교차로(북·남은 둔산중로, 동·서는 둔산로를 건넘)로 묶이고, 1번→5번 출구처럼 대각선으로 갈 때 신호를 보면 평균 30초 넘게 빨라집니다. |
| 실시간 신호 잔여시간 | 대전은 도로교통공단 실시간 신호정보 서비스 지역이지만 내비 회사에만 제공됩니다. 서울 T-Data 같은 개인용 공개 API는 확인되지 않았습니다. |
| 신호 운영 계획 | 경찰청 도시교통정보센터(UTIC) '신호 개방 데이터'가 인천·대전·대구의 교차로 기반정보, 현시구성, TOD 계획, 시그널맵(보행맵 포함)을 하루 한 번 제공합니다. 시뮬레이션 대신 실제 주기·현시로 바꾸는 다음 단계의 재료입니다. |
| 신호등 위치 | 공공데이터포털 '대전광역시_신호등조회서비스'가 신호등 위치와 종류(보행자 신호등 등), 작동 방식을 제공합니다. |
| 긴급차량 우선신호 | 2026년 4월부터 소방서 주변 9개 출동로에서 긴급차량 우선신호가 운영됩니다. 이 구간은 출동 중 신호가 계획과 달라질 수 있습니다. |

실제 지도에서도 신호 시간은 시뮬레이션입니다(횡단 길이로 보행 녹색을 정하고, 교차로마다 옵셋을 다르게 둡니다).
실시간 서버를 연결하면 `server/intersections.json`에서 OSM 교차로 id(`i…`)에 `itstId`를 붙여 같은 방식으로 실제 신호를 넣을 수 있습니다.

**미리 받아 둔 지도.** 공개 Overpass 서버는 자주 바빠서(HTTP 503·504) 휴대폰에서 바로 받으면 실패할 때가 많습니다.
그래서 넷리파이 빌드 때 `tools/fetch-osm.mjs`가 목록(`src/places.js`)의 장소마다 반경 700 m 지도를 받아 `data/`에 둡니다.
앱은 목록의 장소를 고르면 이 파일을 먼저 읽고, 없을 때만 Overpass에 직접 요청합니다. 빌드 때 받지 못한 장소는 빌드를 멈추지 않고 건너뜁니다.
어떤 장소가 준비됐는지는 배포된 사이트의 `data/index.json`에서 볼 수 있습니다. 새로 받으려면 다시 배포하면 됩니다.

'내 위치'와 '지금 보는 곳'은 브라우저가 Overpass API에 직접 요청합니다(claude.ai 아티팩트 링크에서는 외부 요청이 막혀 있어 넷리파이 같은 일반 주소에서 열어야 합니다). 실패하면 서버별 이유(HTTP 504, 시간 초과 등)를 지도 창에 보여줍니다.
`server/server.mjs`가 떠 있으면 `/api/osm`을 통해 받아오고 같은 영역을 하루 동안 디스크에 캐시합니다. `--mock`이면 대전 영역은 실제 대전 시청역 데이터(`test/fixtures/daejeon-cityhall.json`), 그 밖은 합성 데이터(`test/fixtures/osm-sample.json`)를 줍니다.

## 실행

```bash
# 정적으로만 쓰기: docs/crosswalk/index.html 을 열거나 호스팅
# 로컬 서버 + 모의 실시간 신호(키 없이 연결 흐름 확인)
node server/server.mjs --mock
# → http://localhost:8787  설정 > 실시간 신호 서버 에 http://localhost:8787 입력 후 '연결'
```

## 실제 신호 데이터 연결 (서울)

1. [서울 교통빅데이터 플랫폼 T-Data](https://t-data.seoul.go.kr)에서 **신호제어기 신호 잔여시간 정보서비스** Open API를 신청해 인증키를 받습니다.
   응답에는 교차로마다 `ntPdsgRmdrCs`(북쪽 보행신호 잔여, 1/10초), `ntPdsgStatNm`(상태) 같은 방향별 보행 신호 필드가 들어 있습니다.
2. `server/intersections.json`에 데모 교차로와 실제 교차로 ID(`itstId`)를 연결합니다. 교차로 ID와 위치는 T-Data의 교차로 정보 데이터셋에서 찾습니다.
   단일로 횡단보도처럼 방향 이름이 다른 경우 `legMap`으로 데모의 횡단보도 이름(`nt`·`et`·`st`·`wt`·`xw`)을 T-Data 방향 필드에 맞춥니다.
3. 서버를 띄우고 앱의 설정에서 서버 주소를 넣어 연결합니다.

```bash
TDATA_API_KEY=발급받은키 node server/server.mjs
# 선택: TDATA_ENDPOINT(기본 fusion 1.0), TDATA_REMAIN_DIVISOR(기본 10), PORT(기본 8787)
```

프록시는 교차로별 응답을 1초 캐시해 정리된 형태로 돌려줍니다.

```json
{ "mode": "live", "intersections": { "gangnamdaero|teheranro": { "legs": { "nt": { "state": "red", "remain": 42.3 } } } } }
```

앱은 받은 잔여시간을 그대로 보여주고, 미래 시각(경로 계산)은 교차로의 주기 계획을 관측값에 맞춰 옵셋을 보정해 예측합니다.
서울 밖 지역은 도로교통공단이 전국으로 넓히고 있는 실시간 신호정보에 같은 방식으로 붙일 수 있습니다.

## 구조

```
docs/crosswalk/
  index.html          빌드 결과(이 파일만 있으면 동작)
  src/
    geo.js            위경도 ↔ 로컬 미터 좌표, 표시 형식
    signal.js         신호 운영 계획, 상태·잔여시간 계산, 실시간 관측값으로 옵셋 보정
    network.js        데모 도로망(교차로·보도·횡단보도·지하보도) 생성
    routing.js        시간 의존 다익스트라, 경로 평가, 횡단 순서 안내, 출발 여유
    osm.js            OpenStreetMap(Overpass) 질의와 보행 그래프·교차로·그리기 레이어 생성
    places.js         불러오기 장소 목록(앱과 미리 받기 스크립트가 같이 씀)
    app.js            지도 그리기, 상호작용, 패널, 지도 바꾸기
    page.html         마크업과 스타일
  build.mjs           src/ 를 index.html 로 묶기 (node build.mjs)
  tools/fetch-osm.mjs 넷리파이 빌드 때 장소별 지도를 data/ 에 미리 받기
  netlify.toml        빌드 명령(미리 받기), 게시 폴더
  server/
    server.mjs        정적 파일 + /api/signals 프록시 + /api/osm 프록시(캐시) (--mock 지원)
    tdata.js          T-Data 응답 정리
    intersections.json  데모 교차로 ↔ itstId 연결표
  test/               node --test 'test/*.test.mjs' (fixtures/make-osm-fixture.mjs 가 합성 OSM 데이터를 만든다)
```

## 한계와 다음 단계

- 실제 지도는 OpenStreetMap에 보도와 횡단보도가 그려진 만큼만 정확합니다. 강남역 주변 1.5 km 영역에 보도 way가 76개, 횡단보도 way가 55개 있어 큰 교차로 근처는 쓸 만하지만, 보도가 없는 구간에서는 경로가 골목으로 돌아갑니다.
- 실제 데이터 처리는 대전 시청역 주변의 실제 OpenStreetMap 데이터(2026-10-05, `test/fixtures/daejeon-cityhall.json`)와 합성 데이터로 검증했습니다. 더 넓은 영역에서 이상하면 지도 시트의 통계(길·횡단보도·교차로 수)를 알려주세요.
- 실시간 데이터는 센터에 연결된 교차로만 있습니다. 버튼식·감응식 신호는 잔여시간이 확정되지 않아 평균값으로 다뤄야 합니다.
- 보행 신호 주기(동서 직진 → 좌회전 → 남북 직진 → 좌회전)는 서울의 일반적인 4현시를 단순화한 것입니다.
- 위치 기능은 HTTPS 환경에서만 동작하고, 데모 지역 밖이면 거리만 알려줍니다.
