# 초록불 내비

횡단보도 보행 신호의 잔여시간을 보고 걷는 길찾기 프로토타입입니다.
차량 내비가 "몇 초 뒤 초록불"을 보여주듯, 걷는 사람에게 횡단보도의 다음 초록불까지 남은 시간을 보여주고,
**거리만 본 경로**와 **신호를 본 경로**를 비교해 어디서 언제 건너는 게 빠른지 알려줍니다.

- `index.html` 하나로 동작합니다. 그대로 열거나 정적 호스팅(GitHub Pages, Netlify)에 올리면 됩니다.
- 신호는 기본적으로 **시뮬레이션**입니다. 서울 T-Data 인증키가 있으면 `server/`의 프록시로 실제 교차로 신호를 받아옵니다.
- 지도는 강남 테헤란로 일대(강남역·역삼역·선릉역·신논현역·언주역·선정릉역)를 실제 거리로 그린 **개략도**입니다.

## 무엇을 보여주나

| 화면 | 내용 |
|---|---|
| 지도 | 횡단보도마다 지금 신호(초록/빨강)와 남은 초 수. 누르면 잔여시간 표시기(LED) 카드가 열립니다. |
| 횡단보도 카드 | 다음 초록불까지 남은 시간, 지금 건너면 몇 초 남기고 도착하는지, 다음 초록불이 켜지는 시각 |
| 경로 비교 | 거리만 본 경로와 신호를 본 경로의 소요 시간·대기 시간·도착 시각, 횡단 순서 안내, 출발을 늦춰도 되는 여유 |

경로는 **시간 의존 최단경로**로 계산합니다. 보도는 거리 ÷ 보행 속도, 횡단보도는 도착 시각의 신호 상태에 따라 대기 시간이 붙습니다.
남은 초록불이 "횡단 시간 + 여유"보다 짧으면 다음 신호를 기다리는 것으로 계산하므로 뛰어서 건너는 경로는 만들지 않습니다.

## 실행

```bash
# 정적으로만 쓰기: docs/crosswalk/index.html 을 열거나 호스팅
# 로컬 서버 + 모의 실시간 신호(키 없이 연결 흐름 확인)
node server/server.mjs --mock
# → http://localhost:8787  설정 > 실시간 신호 서버 에 http://localhost:8787 입력 후 '연결'
```

## 실제 신호 데이터 연결 (서울)

1. [서울 교통빅데이터 플랫폼 T-Data](https://t-data.seoul.go.kr)에서 **신호제어기 신호 잔여시간 정보서비스** Open API를 신청해 인증키를 받습니다.
   응답에는 교차로마다 `ntPdsgRmdrCs`(북쪽 보행신호 잔여, 1/10초), `ntPdsgStatNm`(상태) 같은 방향별 보행 신호 필드가 들어 있습니다.
2. `server/intersections.json`에 데모 교차로와 실제 교차로 ID(`itstId`)를 연결합니다. 교차로 ID와 위치는 T-Data의 교차로 정보 데이터셋에서 찾습니다.
   단일로 횡단보도처럼 방향 이름이 다른 경우 `legMap`으로 데모의 횡단보도 이름(`nt`·`et`·`st`·`wt`·`xw`)을 T-Data 방향 필드에 맞춥니다.
3. 서버를 띄우고 앱의 설정에서 서버 주소를 넣어 연결합니다.

```bash
TDATA_API_KEY=발급받은키 node server/server.mjs
# 선택: TDATA_ENDPOINT(기본 fusion 1.0), TDATA_REMAIN_DIVISOR(기본 10), PORT(기본 8787)
```

프록시는 교차로별 응답을 1초 캐시해 정리된 형태로 돌려줍니다.

```json
{ "mode": "live", "intersections": { "gangnamdaero|teheranro": { "legs": { "nt": { "state": "red", "remain": 42.3 } } } } }
```

앱은 받은 잔여시간을 그대로 보여주고, 미래 시각(경로 계산)은 교차로의 주기 계획을 관측값에 맞춰 옵셋을 보정해 예측합니다.
서울 밖 지역은 도로교통공단이 전국으로 넓히고 있는 실시간 신호정보에 같은 방식으로 붙일 수 있습니다.

## 구조

```
docs/crosswalk/
  index.html          빌드 결과(이 파일만 있으면 동작)
  src/
    geo.js            위경도 ↔ 로컬 미터 좌표, 표시 형식
    signal.js         신호 운영 계획, 상태·잔여시간 계산, 실시간 관측값으로 옵셋 보정
    network.js        데모 도로망(교차로·보도·횡단보도·지하보도) 생성
    routing.js        시간 의존 다익스트라, 경로 평가, 횡단 순서 안내, 출발 여유
    app.js            지도 그리기, 상호작용, 패널
    page.html         마크업과 스타일
  build.mjs           src/ 를 index.html 로 묶기 (node build.mjs)
  server/
    server.mjs        정적 파일 + /api/signals 프록시 (--mock 지원)
    tdata.js          T-Data 응답 정리
    intersections.json  데모 교차로 ↔ itstId 연결표
  test/               node --test 'test/*.test.mjs'
```

## 한계와 다음 단계

- 개략도라 실제 보도·건물 배치와 다릅니다. 실제 지도 위에서 쓰려면 OpenStreetMap 보행 네트워크를 불러와 같은 그래프 구조로 만들면 됩니다.
- 실시간 데이터는 센터에 연결된 교차로만 있습니다. 버튼식·감응식 신호는 잔여시간이 확정되지 않아 평균값으로 다뤄야 합니다.
- 보행 신호 주기(동서 직진 → 좌회전 → 남북 직진 → 좌회전)는 서울의 일반적인 4현시를 단순화한 것입니다.
- 위치 기능은 HTTPS 환경에서만 동작하고, 데모 지역 밖이면 거리만 알려줍니다.
