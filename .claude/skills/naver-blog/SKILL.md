# 네이버 블로그 글 자동 작성 (아둘맘 스타일)

사진 몇 장과 짧은 답변만 받아서, 블로그 주인이 평소 쓰던 말투·형식 그대로 **발행 직전 글**을 만든다.
형식의 기준은 오직 `references/` 안의 실제 발행글이다. 새 디자인이나 새 표현을 만들지 않는다.

## 0. 글 종류 고르기 → 레퍼런스 정독

먼저 사진과 첫 메시지로 글 종류를 정하고, **그 폴더의 레퍼런스를 처음부터 끝까지 전부 읽은 다음** 쓴다.
매번 새로 읽는다(기억에 의존하지 않는다).

| 종류 | 폴더 | 예 |
| --- | --- | --- |
| 장소 후기 | `references/place/` | 맛집, 카페, 키즈카페, 나들이, 도서관 |
| 제품 후기 | `references/product/` | 육아템, 체험단·협찬 제품 |
| 자료나눔 | `references/share/` | 직접 만든 앱·인쇄물·루틴표 나눔 (인스타 릴스와 연결) |

애매하면 한 줄로 물어본다.

### 레퍼런스에서 뽑아서 그대로 따를 것
- 인사말 첫 줄과 블로그 닉네임 (가장 최근 글 = `share/01` 의 표기를 기본값으로)
- 장소 후기: 맨 위 **인용구 정보 블록**(상호 / 주소 / 영업시간·라스트오더·휴무 / 편의시설 / 주차) → 인사 → 방문 이유 2~3줄 → **인용구 소제목** 섹션들 → `총평` → 지도
- 제품 후기: 인사 → 아이 개월 수와 고민(왜 쓰게 됐는지) → 인용구 소제목 섹션들 → `정리`(✅ 체크 3~4줄) → 추천 2~3줄 → 맨 끝 가운데 정렬 체험단 문구
- 자료나눔: 인사 + 😊 → 무엇을 나누는지 한 줄 → 엄마 공감(아침 전쟁 같은 장면) → 소제목(h3) 섹션들 → 받는 법
- 문장: 한 줄에 한 문장, 짧게. "~더라고요", "~답니다", "~좋더라고요", "너무 ~", "ㅎㅎ", "😂👍😋" 정도의 이모지. 아이 호칭은 "첫째", "둘째", "셋째".
- 사진 자리마다 사진 1장(또는 2장)과 그 사진을 설명하는 1~3줄이 붙는 리듬.

## 1. 첫 메시지 받으면: 질문 한 번에 묶어서

바로 쓰지 말고, 모르는 것만 번호로 짧게 묶어서 한 번에 묻는다. 답에 이미 있는 건 뺀다.

**장소 후기**
1. 상호와 지역(동 이름까지)
2. 시킨 메뉴 전부 + 가격 (영수증 사진 있으면 거기서)
3. 제일 맛있던 메뉴 1~2개와 한 줄 평
4. 누구랑 갔는지, 아이 개월 수·나이
5. 아이 관련: 아기의자·어린이 메뉴·놀이공간·수유실 유무
6. 분위기 한 단어, 웨이팅 여부, 방문 시간대
7. 주차
8. 협찬·체험단이면 어디서 받았는지
9. 재방문 의향

**제품 후기**
1. 제품명·브랜드·용량/구성
2. 아이 개월 수와 쓰게 된 이유(어떤 고민이 있었는지)
3. 써 보니 좋았던 점 2~3개, 아쉬운 점 있으면 1개
4. 아이 반응 한 장면
5. 사용 기간
6. 협찬·체험단·쿠팡 파트너스 여부와 제공처

**자료나눔**
1. 무엇을 나누는지(앱/인쇄물), 누가 쓰면 좋은지(개월 수)
2. 만든 이유가 된 우리 집 장면
3. 기능 3~4개
4. 받는 법(링크, 인스타 댓글 키워드 등)

빠진 답이 있으면 짧게 한 번만 더 묻는다.

## 2. 사실 확인

- 장소 후기는 웹 검색으로 주소·영업시간·라스트오더·휴무·전화·주차를 찾아 정보 블록을 채운다. 체인이면 다른 지점명을 나열하지 않는다.
- 찾았는데 확실하지 않은 값, 못 찾은 값은 `[확인 필요: 영업시간]` 처럼 칸으로 남긴다. 추측해서 채우지 않는다.
- 출처 문구("웹 검색 기준…")는 본문에 쓰지 않는다. 대신 마지막 안내 메시지에서 확인할 칸을 알려 준다.

## 3. 글쓰기 규칙

1. 메뉴·기능·장점은 **사용자가 말한 것만** 쓴다. 사진에 보이는데 답에 없으면 "이것도 시키셨어요?"로 확인한다. 검색에서 본 다른 인기 메뉴는 넣지 않는다.
2. 가격은 메뉴마다 쓴다. 모르면 `[가격 확인 필요]`.
3. 과장 금지: "인생 맛집", "무조건 가세요", "강력 추천" 같은 말은 레퍼런스에도 없으니 쓰지 않는다. 레퍼런스 수준의 "추천해 드려요"까지만.
4. 정보 블록에 쓴 내용(주소·주차 등)은 본문에서 다시 길게 반복하지 않는다. 인사 뒤 방문 이유에서 한 번 짧게 언급하는 정도는 레퍼런스처럼 괜찮다.
5. **광고 표시(공정위)**
   - 체험단·협찬: 맨 끝 가운데 정렬로 `본 포스팅은 [제공처]로부터 제품을 제공받아 솔직하게 작성한 리뷰입니다.` (레퍼런스 문구 그대로)
   - 쿠팡 파트너스 링크가 들어가면: **제목 바로 아래 첫 줄**에 `이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.` 를 넣고, 링크는 해당 제품 문단 바로 아래에 둔다.
   - 내 돈 주고 산 거면 아무 문구도 넣지 않는다.
6. 사진 자리는 구체적으로: `[사진: 매장 외관 정면]`, `[사진: 칼국수 클로즈업 — 새우 보이게]`. `[사진]` 만 쓰지 않는다. 사용자가 보낸 사진은 메뉴명 확인·분위기 파악용으로만 쓰고 글에 넣지 않는다.
7. 제목은 레퍼런스처럼 `지역 + 특징 + 상호/제품명` 한 줄 (예: `가족모임으로 좋은 대전 시청역 맛집 담온식당`). 후보 3개를 준다.
8. 해시태그는 끝에 8~12개 (지역·상호·메뉴·아이 개월 수).

## 4. 출력

결과는 두 가지로 만든다.

1. **HTML 파일**: `blog-drafts/YYYY-MM-DD-<짧은이름>.html` (이 폴더는 git에 올리지 않는다). 레퍼런스 구조를 따른 완성 문서(`<!DOCTYPE html>` 부터). 인용구 소제목은 `<blockquote>`, 사진 자리는 `<p class="photo">[사진: …]</p>`. 사용자에게 파일로 보내 준다. 브라우저로 열어 전체 선택 → 복사 → 스마트에디터에 붙여넣으면 문단 그대로 들어간다.
2. **네이버 임시저장(선택)**: Uplika가 연결돼 있으면(`list_accounts` 에서 platform `naver_blog`, handle `theshins1003`) 같은 내용을 markdown으로 바꿔
   `naver_layout` 으로 모양을 먼저 보여 주고, **사용자가 "임시저장 해줘"라고 확인한 뒤에만** `publish` 를 `options.naver_blog.draftOnly: true` 로 보낸다. 바로 발행하지 않는다.
   - markdown의 `##` 소제목이 인용구 소제목으로 바뀐다(레퍼런스 형식과 같다).
   - 사진은 사용자가 네이버 편집기에서 직접 넣는다. 다 넣은 뒤 사용자가 원하면 `list_naver_drafts` → `publish_naver_draft` 로 발행한다(이것도 확인 후에만).
   - 카테고리는 `list_accounts` 의 naverBlog.categories 에서 고른다(장소 → 맛집 또는 아이와일상, 제품 → 아이와일상, 자료나눔 → 주제에 맞는 것: 엄마표수학·넘버블럭스·엄마표영어 등).
   - 확장 프로그램이 꺼져 있으면(bridge offline) 응답의 `userMessage` 를 그대로 전하고, HTML 파일 복붙 방법을 안내한다.

채팅 본문 메시지는 짧게: 제목 후보 3개 + "확인 필요한 칸: …" + "고칠 데 말해 주세요".

## 5. 수정 요청

"도입부 짧게", "별점 빼줘", "메뉴 추가" 같은 요청은 같은 파일을 고쳐서 다시 보낸다. 임시저장까지 했으면 새로 만들지 말고 `update_post` 로 같은 글을 고친다.

## 자주 생기는 문제

- **AI 티가 난다**: 레퍼런스보다 문장이 길어졌다는 뜻이다. 한 줄 한 문장, "~더라고요" 체로 다시 쓴다. 접속사("또한", "뿐만 아니라", "결론적으로")를 지운다.
- **매번 같은 형식**: 섹션 수와 소제목은 사진·메뉴 수에 맞춰 바뀌어야 한다. 레퍼런스 4개도 섹션 수가 다 다르다.
- **레퍼런스 추가**: 새로 마음에 드는 글을 발행하면 `references/<종류>/` 에 넣는다. 모바일 주소(`m.blog.naver.com/theshins1003/<글번호>`)를 받아서 본문만 정리해 저장하면 된다.
